tunnelr - expose ports of your local machine through a cheap VPS.

How it works:

  1. On the VPS run the tunnelr server. It listens on the tunnel port and
     prints its address and a secret key.
  2. On your machine run the tunnelr client with that address and key. It asks
     the server to open the public ports you want.
  3. Anyone who connects to <vps>:<public port> reaches the app port on your
     machine. Public ports open when the client connects and close when it
     disconnects.

Ports:

  visitor from the internet
     |
     v
  vps:30185        public port  (one per forwarded app)
  vps:20185        tunnel port  (one per server, the client connects to it)
     ^
     || tunnel
  tunnelr client on your machine
     |
     v
  127.0.0.1:3000   app port     (where your app listens)

  Tunnel port  On the VPS, one per server (default 4000). tunnelr clients
               connect to it, the HTTP API runs on it too. Server: -p 20185,
               client: <vps host>:20185.
  Public port  On the VPS, one per forward. Visitors from the internet connect
               to it. Client: -p 30185.
  App port     On your machine (or the --to host), where your app listens.
               Client: -p 30185:3000. Without ":3000" it is the same as the
               public port.

  The tunnel port and every public port have to be ports the VPS really has
  open. Cheap providers forward only a few, mikr.us gives two, like 20185 and
  30185: one tunnel port and one public port.

Usage:

  tunnelr server [-p <tunnel port>] [options]
      start the server (on the VPS)
  tunnelr <vps host[:tunnel port]> -p <public port>[:<app port>]
      start the client (on your machine)
  tunnelr add <name> <vps host[:tunnel port]> -p <public port>[:<app port>]
      save a connection
  tunnelr [<name>] [-p <public port>[:<app port>]]
      open a saved connection (default: last used)
  tunnelr ls | rm <name>
      list or remove saved connections
  tunnelr server --uninstall
      remove the systemd service
  tunnelr token [-a <key or file>]
      print a one-time token for the HTTP API
  tunnelr update
      install the latest version
  tunnelr help | version

Server (on the VPS):

  sudo tunnelr server -p 20185

  As root on Linux with systemd this installs (or updates) the "tunnelr"
  service, starts it and prints the address and the key. The service starts
  again after every reboot. Run the same command again anytime to see the
  address and key. Without root or systemd the server runs in the foreground.

  -p, --tunnel-port <port>
                         Tunnel port (default 4000). tunnelr clients connect to
                         it. Public ports are not set here, the client asks for
                         them.
  -a, --auth <key|file>  Key, or path to a file with the key. Default file:
                         ~/.tunnelr/key. A new key is created and saved
                         there when the file is missing.
  --foreground           Do not touch systemd, run in the foreground.
  --bind <address>       Listen only on this address (default: all interfaces).
  --uninstall            Stop, disable and remove the systemd service.

  Check the service with:  systemctl status tunnelr  |  journalctl -u tunnelr -f

Client (on your machine):

  tunnelr my-vps.example.com:20185 -p 30185:3000 -a ~/.tunnelr/key
  tunnelr my-vps.example.com -p 3000 -a ~/.tunnelr/key
  tunnelr my-vps.example.com -p 3000,5000,8000
  tunnelr my-vps.example.com:2500 -p 3000

  <host[:tunnel port]>   VPS host name or IP and the tunnel port of the
                         server (default 4000). Use wss://host:port when a TLS
                         proxy is in front.
  -p, --port <public port>[:<app port>]
                         Public port to open on the VPS (it must be open
                         there) and the app port on your machine it forwards
                         to (default: the same number). Separate many with
                         commas or repeat the flag.
  -a, --auth <key|file>  Key, or path to a file with the key.
                         Default: ~/.tunnelr/key.
  --to <host>            Host to forward to (default: 127.0.0.1). Use it when
                         the service runs elsewhere in your LAN or in a
                         container without a published port.

  The client reconnects by itself when the connection drops.

Saved connections (on your machine):

  tunnelr add vps 203.0.113.10:20185 -p 30185:3000 -a ~/.tunnelr/key
  tunnelr                  open the last used connection with its saved ports
  tunnelr -p 5000          same, but forward public port 30185 to app port 5000
  tunnelr vps -p 30186:80  open "vps" with other ports
  tunnelr ls               list saved connections, "*" marks the last used one
  tunnelr rm vps           remove one

  "add" takes the same flags as the client (-p, -a, --to) and replaces
  a connection with the same name. Flags given when opening a connection win
  over the saved ones. A bare port in -p keeps the saved public port at the
  same position and changes only the app port, "public:app" is taken as is.
  Connections are kept in ~/.tunnelr/connections.json (the key file
  path is saved there, not the key).

Auth:

  The key never travels over the network. Every request carries a one-time
  token signed with the key that expires after a minute, so a captured token
  cannot be reused. Both machines need a correct clock.

HTTP API (on the tunnel port):

  GET /ports          list open public ports and their clients
  DELETE /ports/<n>   close public port n, its client is told about it
  GET /               server name and version, no token needed

  Send a token in "Authorization: Bearer <token>" or "?token=<token>":

    curl -H "Authorization: Bearer $(tunnelr token)" http://my-vps.example.com:20185/ports
    curl -X DELETE -H "Authorization: Bearer $(tunnelr token)" http://my-vps.example.com:20185/ports/3000

  Public ports are opened by the client, so there is no POST endpoint.

Updating:

  tunnelr update downloads the latest release and replaces the binary (use
  sudo when it is installed in a system directory, then restart the service
  with: sudo systemctl restart tunnelr). tunnelr checks for a new version once
  a day and prints a notice, TUNNELR_NO_UPDATE_CHECK=1 turns that off.

Other:

  --debug     Print debug logs
  -h, --help  Show this help
  -v, --version

Note: traffic between the client and the server is not encrypted by tunnelr.
Use HTTPS or SSH inside the tunnel, or put a TLS proxy in front of the server.
