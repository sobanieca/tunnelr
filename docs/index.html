tunnelr
GitHub

Put localhost on the internet through a VPS you already pay for.

tunnelr is one small binary. Run it as a server on a cheap VPS, run it as a client on your machine, and a public port on the VPS reaches the port your app listens on, on your laptop.

A visitor hits the VPS on the public port. The client keeps a tunnel open to the server's tunnel port, takes the connection over it and opens a TCP connection to the app port on your machine. Many connections share one WebSocket.

One binary, two roles

tunnelr server installs itself as a systemd service and survives reboots. Without server it is the client.

Two open ports are enough

Cheap providers expose a couple of ports. One becomes the tunnel port, the other your public port. That is the whole requirement.

Reconnects on its own

Wi-Fi drops, laptop sleeps, the client backs off and comes back. A new client for the same port takes over the old one.

Saved connections

tunnelr add vps … once, then plain tunnelr reopens it. Only the path to the key file is saved.

Three ports, three names

Every flag, message and help text in tunnelr uses these names. The tunnel port and each public port must be open on the VPS.

20185

Tunnel port

Where
VPS, one per server
Who
the tunnelr client, and the HTTP API
Set
server -p 20185, client vps:20185
30185

Public port

Where
VPS, one per forwarded app
Who
visitors from the internet
Set
client -p 30185:3000, left side
3000

App port

Where
your machine, or the --to host
Who
tunnelr, to reach your app
Set
client -p 30185:3000, right side
$ tunnelr 203.0.113.10:20185 -p 30185:3000
                       │        │     └─ app port     where your app listens
                       │        └─────── public port  what visitors open
                       └──────────────── tunnel port  where the server listens

Setup, in full

  Tunnel port:   20185
  Key:           kD3xW9q1mZ8pR4tY7uH2cV6bN0aS5fGj
  Key file:      /root/.tunnelr/key

Your machine whenever

$ curl -fsSL adam.sobaniec.com/tunnelr/install.sh | bash
$ echo kD3x… > ~/.tunnelr/key
$ tunnelr 203.0.113.10:20185 -p 30185:3000

Install

curl -fsSL adam.sobaniec.com/tunnelr/install.sh | bash

Same command on the VPS and on your machine: a single binary for Linux and macOS (x64 and arm64), no runtime needed. Debian is the tested server OS. Update it any time with tunnelr update. tunnelr --help lists every option and the small HTTP API (on the tunnel port) for listing and closing public ports.

It installs to ~/.tunnelr/bin, with no sudo needed, and asks to add that folder to your PATH in your shell's startup file. Set TUNNELR_NO_MODIFY_PATH=1 to leave the file unchanged, or install to another folder with INSTALL_DIR, as in curl -fsSL adam.sobaniec.com/tunnelr/install.sh | INSTALL_DIR=~/.local/bin bash. On the VPS, pipe it to sudo bash: run as root, it installs to /usr/local/bin, where sudo tunnelr server finds it.
